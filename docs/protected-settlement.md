# Protected Settlement — Mumbai Continuity

Baseline: `89c4a7910f054042872927a29e162538f6fa7b65` (September 13, 2026).

FirmDepth already provided maker-signed collateral-backed commitments, Aqua and bond settlement, FIRM_PRICE/FIRM_GUARD, pricing v2, SDK receipts, and a Sepolia demo. The Mumbai extension composes those contracts into treasury payouts. It adds a contract taker, immutable payer-owned allocations, isolated WETH funding, atomic downstream USDC transfers, expiry refunds, quote integration, and a settlement UI. It does not introduce a new underlying swap protocol.

## Lifecycle

Payer creates an immutable plan → payer approves and funds WETH principal plus premium budget → maker signs a quote naming the settlement contract as taker → payer accepts through the wrapper → registry escrows premium and locks maker collateral → payer executes through the wrapper → existing executor settles through Aqua or covered bond → wrapper distributes all allocations and returns surplus/unused premium budget atomically.

`CREATED → FUNDED → ACCEPTED → SETTLED`; cancellation before acceptance or expiry afterward leads to `REFUNDED`. Each plan ID binds chain, wrapper, payer, and nonce. Payer calls authorize the plan; there is no delegated signature or relayer feature. Up to 32 unique recipients receive fixed amounts. The payer always owns surplus and refunds.

The accepted quote does not need a new signed field: only the payer can bind it to their immutable plan; the registry consumes the maker nonce and the wrapper permanently associates its digest with that plan. Both acceptance and execution have separate transactions. The quote's signed expiry must be within the plan deadline.

## Security assumptions

Only exact-transfer WETH/USDC semantics are supported. The wrapper uses SafeERC20, non-reentrancy, exact balance changes, temporary exact allowances, per-plan escrow and aggregate liabilities. Unsolicited token donations are not credited or sweepable. There is no admin rescue facility.

Recipient payouts happen inside the same transaction as FirmExecutor.execute. A failure on any recipient reverts earlier transfers, registry finalization, premium payment, collateral release and the underlying swap. Unknown failures never select the bond path. An accepted plan can be retried until its deadline. Recipient freezes or token failures can prevent execution; after expiry the payer can recover unspent principal and unused premium budget. The accepted premium remains payable to the maker. This is execution protection against v1's covered capacity failures, not universal payment availability.

Expiry may be finalized by any caller directly on v1's registry; the payer can still recover their wrapper escrow afterward. Another payer cannot fund, accept, execute, redirect, or withdraw a plan. Fully settled plans cannot execute again.

No core v1 Solidity contract was modified. No public Sepolia transaction is required or claimed by this extension.

## Local demonstration

Run from the repository root:

```bash
./scripts/demo_protected_settlement.sh
```

Requires Node 22+, Chrome (or `PLAYWRIGHT_CHROME_PATH`), free ports 8545/4174 and a Base historical RPC. Set `BASE_RPC_URL` for reliable archive access. The public default may rate limit. The runner uses the recorded historical USDC holder through fork-only impersonation; it never sends a mainnet transaction.

The demo uses scaled 120/80 USDC allocations. It verifies a normal Aqua settlement, then accepts another commitment, executes a sibling Aqua swap draining maker inventory to 100 USDC, and proves the 200-USDC commitment still funds both recipients from its bond. Evidence includes genuine local transaction hashes and recipient balance deltas in `packages/contracts/evidence/protected-settlement-fork.json`. These hashes belong to the local fork and are not public explorer transactions.

For an interactive session, start the local Hardhat node using the same flags as the runner, then:

```bash
cd packages/contracts
FIRMDEPTH_FORK_HOLDER=0xb2cc224c1c9feE385f8ad6a55b4d94E92359DC59 npx hardhat run scripts/setup-protected-fork.ts --network localBase
cd ../frontend
npm run dev
```

Open `/settlement`. Use the local fork's payer account (account 2), with test-only wallet handling. The runtime is generated under ignored `.runtime/`. The public Sepolia manifest remains unchanged. The local quote adapter is explicitly fork-only and uses RPC signing with unlocked development accounts. Public quote-service deployments instead use the existing maker signer; setting `FIRMDEPTH_SETTLEMENT_ADDRESS` enables `/quote/settlement` for a compatible deployed wrapper. No public wrapper has been deployed as part of this work.

## Evidence and readiness

Evidence must be regenerated by actual transactions. The committed record includes its execution timestamp, chain/fork identity, addresses and balances. Readiness requires the contract, SDK, service, frontend and fork/browser suites to pass. Test failures, unexecuted checks, and unavailable RPC services must be reported; recorded historical evidence does not prove the current local node or public site is ready.

The clean-start run was executed successfully on November 6, 2026: 82 Solidity tests, 31 SDK tests, 10 quote-service tests, 31 frontend unit tests, the benchmark command, 25 existing browser checks and three protected-settlement browser scenarios passed. Six tests in the general browser invocation were intentionally skipped because they require the separate protected or public-Sepolia mode; the three protected scenarios were then executed separately. Public Sepolia smoke tests were not run.

The separate [local deployment manifest](../deployments/protected-base-fork.json) records the verified deployment and links the evidence. `verify-protected-fork.ts` independently checks deployed bytecode, successful receipts, recipient transfer logs and current balances, the mined failure receipt and vault liabilities. The runner executes this verifier after the demo. `KEEP_LOCAL_FORK=1 ./scripts/demo_protected_settlement.sh` retains the node and generated runtime for inspection; stop the printed PID before rerunning a fresh demonstration.

The failure demonstration temporarily replaces executor bytecode with `REVERT` using a fork-only development RPC and restores it immediately. This is explicitly identified as injected failure evidence. Recipient rejection and malicious-token rollback are covered by contract tests. Actual Aqua and bond success scenarios use unmodified executor code.
